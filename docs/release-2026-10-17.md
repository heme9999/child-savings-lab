# October 17 design-engineering refinements

## Scope

The user authorized implementing the eight findings from the overall Emil design-engineering audit, synchronizing GitHub, and deploying the existing Cloudflare Pages site. The implementation also follows mobile-native platform guidance. It retains the warm, editorial brand and adds no animation library, decorative number animation, or new financial feature.

Eligibility rules, calculation formulas, source records, policy-review dates, calculation version, privacy safeguards, canonical routes, and Search Console configuration are unchanged. This is interface work, not a new legal, tax, investment, or benefits review.

## Changes

| Before | After | Why |
| --- | --- | --- |
| Gold focus rings contrasted only 2.38–2.62:1 on light backgrounds | Dark ink on light surfaces; gold on dark panels, footer, topic panel, and scenario continuation link; the latter uses an inset outline | Keep keyboard focus visible; automated checks require at least 3:1 for each tested surface |
| Long native select labels were clipped on phones | Short display labels plus full wrapping explanations associated with `aria-describedby` | Preserve every account-state value and legal qualifier without hiding the selected meaning |
| Large tools-directory introduction and stacked article metadata/contents delayed useful content | Compact directory header; visible review dates with native scope/publication disclosure; native collapsible contents; early five-account purpose overview | Put tools and answers ahead of secondary detail without removing the detail |
| All four growth figures were equally sized and smaller than the result heading | A full-width primary balance, quieter secondary metrics, and a smaller result heading | Make the answer easier to find |
| A funding explanation was styled as a large multiline pill | Short status label followed by the complete original guidance | Separate status from explanation; reported activation is not a new eligibility determination |
| Global smooth scrolling also affected keyboard anchors/errors | Immediate document scrolling by default; existing explicit result positioning remains instant | Avoid animation delays on keyboard workflows |
| Entire result panels were atomic live regions | Separate persistent, initially empty status nodes with short update messages; detailed panels are not live regions | Reduce potential repeated/verbose announcements; actual screen-reader behavior still requires testing |
| Preview units, chart labels, and explanations were 10–12px | These preview elements use at least 14px at the default root size; native return input remains 16px | Improve reading comfort without disabling zoom |

The browser exposed a native Reset ordering issue during implementation: a microtask could read the old select value before its default reset action. Description synchronization now occurs in the next task and cancels pending work on cleanup. Added tests reproduce the event/default-action ordering and pending-reset cleanup.

Article publication and effective-scope details remain in the HTML and are also included in the print presentation. Disclosure controls work without JavaScript. Calculator submissions remain disabled until local scripts load; CSP still blocks network form submission.

## Verification

- `npm run verify` passed: Astro diagnostics on 69 files with zero errors/warnings/hints, 181 tests in 12 files, static build, 19 public routes plus genuine 404/sitemap/internal-link consistency checks, and generated HTML validation.
- Added 16 tests for concise announcements, short labels with full qualifiers, description synchronization and reset lifecycle, focus contrast, immediate scrolling, metric hierarchy, and preview text sizing. Build validation also rejects whole-panel live regions, missing announcement nodes, lost compact review metadata, and a missing comparison overview.
- Actual local built-preview checks completed at 390×844, 320×740, and 1280×900. Observed results:
  - The first tools-directory button moved from about 852px to 670px at 390px width; its bottom is 720px.
  - The first purpose-overview answer appears at 476px rather than the previous comparison content at about 1003px.
  - The main guide's summary begins at 501px and ends at 754px. Detailed policy text and the original current-status callout remain present.
  - Native contents open using Enter and keyboard anchor navigation reports `scroll-behavior: auto`, positioning the target immediately.
  - Long select meanings wrap fully; native Reset restores both the value and its explanation.
  - Missing birth date produces linked validation feedback; unknown answers remain unassessed, not an eligibility denial.
  - Growth balances remain visible after submit at 320px width (balance bottom about 265px). The desktop balance is 48px versus 19.2px secondary figures.
  - Invalid 0.2% fund fee opens advanced inputs, marks the field, hides old output, and disables printing; 0.004% retains its full report precision.
  - All three desktop directory actions align at 750.31px. Home and tested tools have no horizontal overflow at the checked widths.
  - No captured browser warnings/errors during these checks.

These are browser viewport and DOM checks, not physical-phone or assistive-technology certification. VoiceOver/NVDA announcements, actual iOS keyboard/zoom, and physical touch behavior remain unverified.
